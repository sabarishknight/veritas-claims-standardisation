# Infrastructure

Terraform for the GCP topology in [`../docs/architecture.md`](../docs/architecture.md).
Committed because an architecture diagram is a claim and this is the evidence.

```bash
cd infra
terraform init
terraform apply -var project_id=YOUR_PROJECT -var region=asia-south1 \
                -var image=REGION-docker.pkg.dev/PROJECT/veritas/veritas:latest \
                -var alert_email=oncall@example.com
```

## What it creates

| resource | purpose |
|---|---|
| GCS landing bucket | clinic drop zone, versioned, 90-day dead-letter lifecycle |
| Pub/Sub topic + push subscription | object-finalise notifications, 7-day retention, DLQ after 5 attempts |
| Cloud Run `processor` | the pipeline; min 1 / max 10 instances, concurrency 20 |
| Cloud Run `ui` | read-only ops dashboard, scales to zero, IAP only |
| BigQuery dataset | partitioned, clustered; DDL generated by `veritas ddl --dialect bigquery` |
| Secret Manager | HMAC key for PII tokenisation; readable by the processor only |
| Cloud Scheduler | hourly reconciliation sweep for missed notifications |
| Log-based metrics + 4 alert policies | error rate, lag, misalignment, dead-letter spike |

## Notes on the choices

**Region `asia-south1`.** Indian patient data stays in India. Changing it is a
data-residency decision, not a latency one.

**Two service accounts.** The UI can read BigQuery and nothing else - in
particular it cannot read the PII key, so the dashboard shows tokens and never
the means to generate or check them.

**`min_instance_count = 1` on the processor.** One instance covers 200,000
files/day at the measured rate; the minimum removes cold start from the latency
budget and the maximum of 10 is headroom for a zone failure, not throughput.
See [`../docs/cost-model.md`](../docs/cost-model.md).

**The misalignment alert has no threshold.** One occurrence pages, because a
clinic silently emitting unusable reports is worse than a clinic emitting
obviously broken ones.
